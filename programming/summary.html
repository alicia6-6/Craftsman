구조적 프로그래밍: C언어 기초문법

변수·자료형·연산자·순차구문을 정확히 이해하면 코드 추적(트레이싱) 문제를 빠르게 풀 수 있습니다.

자료형설명예시
int정수형int a = 10;
float / double실수형(단precision/배정도)float f = 3.14;
char문자형(1바이트)char c = 'A';
기출 함정: 정수 나눗셈
int a = 7, b = 2; float result = a / b;의 결과는 3.5가 아니라 3.0입니다. a/b가 먼저 정수형 나눗셈(7/2=3)으로 계산된 뒤에야 float로 변환되기 때문입니다. 정수끼리 나눌 때는 소수점이 버려진다는 점을 반드시 기억하세요.

연산자 우선순위 핵심

대표 계산 예시

2 + 3 * 4 → 곱셈이 먼저 → 2+12 = 14
a=5; b=a++; → b는 증가 전 값(5)을 받고 a는 6이 됨 (후위 증가)
a=5; b=++a; → a가 먼저 6이 된 후 b도 6 (전위 증가)

선택구문·반복구문·컴파일러

1. switch문의 fall-through 함정 (★단골 출제)

기출 함정
switch(n){ case 1: printf("A"); case 2: printf("B"); break; default: printf("C"); }에서 n=1이면 "AB"가 출력됩니다. case 1에 break가 없으면 다음 case로 그대로 "흘러 내려가기(fall-through)" 때문입니다.

2. for / while / do-while 비교

구문조건 검사 시점최소 실행 횟수
for / while반복 시작 전에 검사0회 (조건이 처음부터 거짓이면 한 번도 안 돎)
do-while반복 실행 후에 검사최소 1회는 반드시 실행

3. 컴파일러 vs 인터프리터

  • 컴파일러: 소스 전체를 한 번에 기계어로 번역 후 실행 파일 생성 (예: C, C++). 실행 속도가 빠름.
  • 인터프리터: 한 줄씩 해석하며 즉시 실행, 별도의 실행 파일을 만들지 않음 (예: Python, JavaScript 초기 실행 방식). 디버깅과 이식성에 유리.
  • 컴파일 과정 순서: 어휘분석 → 구문분석 → 의미분석 → 코드생성 → 최적화

객체지향 프로그래밍(OOP) 4대 특성

2026년 신출제기준의 핵심 신설 영역입니다. 4대 특성의 정의와 구분이 매 시험 출제 1순위입니다.

특성의미핵심 키워드
캡슐화데이터+메서드를 하나로 묶고 내부 구현을 은닉정보 은닉, private
상속부모 클래스의 속성·기능을 자식 클래스가 재사용extends, 재사용
다형성같은 이름의 메서드가 객체에 따라 다르게 동작오버라이딩/오버로딩
추상화공통 특성만 뽑아 일반화, 세부 구현은 감춤추상클래스, 인터페이스
기출 함정: 오버로딩 vs 오버라이딩
오버로딩(Overloading)은 같은 클래스 안에서 매개변수의 개수·타입이 다른 같은 이름의 메서드를 여러 개 정의하는 것이고, 오버라이딩(Overriding)은 부모 클래스의 메서드를 자식 클래스가 같은 시그니처로 재정의하는 것입니다. 다형성은 주로 오버라이딩과 관련됩니다.
  • 동적 바인딩(Dynamic Binding): 실제로 호출될 메서드가 컴파일 시점이 아니라 실행(런타임) 시점에 객체의 실제 타입에 따라 결정되는 것. 다형성 구현의 핵심 메커니즘.
  • 클래스 vs 객체: 클래스는 설계도(틀), 객체는 클래스로부터 실제 생성된 인스턴스.
  • 생성자(Constructor): 객체 생성 시 자동 호출되어 초기화를 수행하는 특수 메서드.

옛 PC운영체제 과목의 Windows98/DOS 특정 조작법은 전부 폐기되었지만, UNIX 명령어와 OS 이론(교착상태, 스케줄링 등)은 그대로 출제됩니다.

2. OS 핵심 이론 용어

  • 교착상태(Deadlock): 다중 프로그래밍 환경에서 둘 이상의 프로세스가 서로 상대방이 점유한 자원을 무한정 기다리며 진행이 멈추는 상태.
  • 시분할 시스템(Time Sharing System): 여러 사용자가 터미널로 동시 접속해, 각자 짧은 타임 슬라이스만큼 CPU를 배분받아 마치 단독 사용하는 것처럼 느끼게 하는 방식.
  • 일괄처리(Batch Processing): 작업을 모았다가 일정 시점에 한꺼번에 처리하는 방식.
  • 가상기억장치: 보조기억장치의 일부를 주기억장치처럼 사용해 실제 용량보다 큰 프로그램을 실행할 수 있게 하는 기법.
  • 커널(Kernel): 프로세스·메모리·파일 관리 등 OS의 가장 핵심적인 기능을 수행하는 부분. UNIX의 3대 요소는 커널·셸(Shell)·파일시스템.
  • I-node: UNIX 파일시스템에서 각 파일·디렉터리의 소유자·권한·크기 등 모든 메타정보를 담는 자료구조.
02 · 응용SW 기초 > 데이터베이스 기초 ★최신개정

데이터베이스 개념과 E-R 모델링

  • DBMS(데이터베이스 관리시스템): 데이터의 중복을 최소화하고 여러 응용프로그램이 데이터를 공유할 수 있게 관리하는 소프트웨어.
  • 데이터베이스 3단계 스키마: 외부 스키마(사용자 관점) - 개념 스키마(전체 논리 구조) - 내부 스키마(물리적 저장 구조)
  • 데이터 모델링 단계: 개념적 설계(E-R 다이어그램) → 논리적 설계(테이블 구조 확정) → 물리적 설계(저장 방식 결정)

E-R 모델 표기법

도형의미
사각형개체(Entity)
타원속성(Attribute)
마름모관계(Relationship)
선(Line)개체와 속성/관계의 연결

데이터베이스 유형

  • 관계형(Relational): 테이블(행·열) 구조로 데이터를 표현. 현재 가장 널리 사용 (예: Oracle, MySQL).
  • 계층형(Hierarchical): 트리 구조로 데이터를 표현, 1:N 관계에 적합.
  • NoSQL: 고정된 테이블 스키마 없이 유연하게 대용량 데이터를 다루는 최신 방식 (예: MongoDB).
02 · 응용SW 기초 > 데이터베이스 기초 ★최신개정

데이터 무결성과 자료구조 기본

무결성 종류의미
개체 무결성기본키(Primary Key)는 NULL이 될 수 없고 중복될 수 없다
참조 무결성외래키(Foreign Key) 값은 참조하는 테이블에 실제로 존재하는 값이거나 NULL이어야 한다
도메인 무결성컬럼 값은 정의된 데이터 타입·범위를 벗어날 수 없다

SELECT 기본 구조와 실행 순서

SELECT 컬럼 FROM 테이블 WHERE 조건 GROUP BY 그룹기준 HAVING 그룹조건 ORDER BY 정렬기준;
실제 처리 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
WHERE는 그룹화 전 개별 행 필터링, HAVING은 그룹화 후 집계결과 필터링에 사용합니다.

JOIN 종류

JOIN 종류결과
INNER JOIN양쪽 테이블에서 조건이 일치하는 행만 반환
LEFT OUTER JOIN왼쪽 테이블은 모두 포함, 오른쪽은 일치하는 것만(없으면 NULL)
RIGHT OUTER JOIN오른쪽 테이블은 모두 포함, 왼쪽은 일치하는 것만(없으면 NULL)

집합 연산자

  • UNION: 두 결과를 합치고 중복 제거
  • UNION ALL: 두 결과를 합치되 중복 포함 (UNION보다 빠름)
  • INTERSECT: 두 결과의 교집합
  • MINUS: 첫 번째 결과에서 두 번째 결과를 뺀 차집합
04 · SQL 작성 및 활용 ★최신개정

DML·DDL·DCL과 트랜잭션

분류명령어기능
DML
(데이터 조작어)		INSERT / UPDATE / DELETE데이터 삽입·수정·삭제 (ROLLBACK 가능)
DDL
(데이터 정의어)		CREATE / ALTER / DROP테이블·인덱스·뷰 등 객체 구조 정의 (실행 즉시 자동 COMMIT)
DCL
(데이터 제어어)		GRANT / REVOKE사용자 권한 부여·회수
기출 함정: DELETE vs TRUNCATE vs DROP
DELETE(DML)는 행 단위로 삭제하며 ROLLBACK으로 취소 가능합니다. TRUNCATE(DDL)는 테이블의 모든 데이터를 한번에 비우며 실행 즉시 자동 커밋되어 되돌릴 수 없습니다. DROP은 테이블 구조 자체를 완전히 삭제합니다.

트랜잭션과 ACID

ACID: 원자성·일관성·고립성·지속성 Atomicity(전부성공 or 전부실패) · Consistency · Isolation · Durability
  • COMMIT: 트랜잭션의 변경사항을 영구 저장
  • ROLLBACK: 트랜잭션의 변경사항을 취소하고 이전 상태로 복구
  • SAVEPOINT: 트랜잭션 중간에 저장점을 지정해, ROLLBACK TO 저장점명으로 특정 지점까지만 되돌릴 수 있게 함

SW 테스트 기법: 단위·통합·블랙박스·화이트박스

구분대상/방식
단위 테스트모듈(함수) 하나하나를 개별 검증
통합 테스트여러 모듈을 결합했을 때 모듈 간 인터페이스 검증 (상향식/하향식)
블랙박스 테스트내부 코드 구조를 보지 않고 입력·출력만으로 검증 (동등분할, 경계값분석 기법)
화이트박스 테스트내부 로직·분기 경로까지 직접 확인 (구문 커버리지 등)
  • 동등분할(Equivalence Partitioning): 입력값을 유효/무효 그룹으로 나누고 각 그룹 대표값만 테스트.
  • 경계값 분석(Boundary Value Analysis): 입력 범위의 경계(최소/최대 근처)에서 오류가 많이 발생하므로 경계값을 집중 테스트.
  • 디버깅(Debugging): 테스트로 발견된 오류의 원인을 찾아 수정하는 과정. 브레이크포인트로 특정 지점에서 실행을 멈추고 상태를 확인.
